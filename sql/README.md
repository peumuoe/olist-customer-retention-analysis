# SQL 버전 (DuckDB)

pandas 파이프라인(`src/`)의 핵심 지표를 SQL로 다시 계산합니다. 원천 CSV(`data/raw/`)를 그대로 읽으며, 결과는 `outputs/sql/`에 저장됩니다.

```bash
pip install duckdb
python sql/run_sql.py
```

`run_sql.py`는 번호 순서대로 쿼리를 실행하고, 고정창 재구매율이 pandas 결과(`src/07`)와 일치하는지 검사합니다.

## 쿼리와 발표 자료 대응

| 파일 | 내용 | 결과 (발표 자료 수치) |
|---|---|---|
| `00_load_raw.sql` | 원천 CSV 뷰 등록 | — |
| `01_retention_orders.sql` | 배송 완료 주문 마트, `ROW_NUMBER()`로 고객별 구매 순서, 첫·두 번째 주문 | 고객 93,358명 |
| `02_retention_windows.sql` | 관찰기간이 보장된 고객만 분모로 쓰는 고정창 재구매율 | 30일 1.58% · 365일 4.53% (대상 86,772 → 21,288명) |
| `03_split_checkout_24h.sql` | 두 번째 주문까지의 시간 분포, 사업 지표 vs 예측 모델용 지표 | 재주문의 30.45%가 24시간 안 · 30일 1.58% vs 24시간 이후 0.62% |
| `04_first_order_category.sql` | 주문 대표 카테고리(`QUALIFY ROW_NUMBER()`), 첫 주문 카테고리별 재구매율과 같은 카테고리 재구매 비율 | 침구·욕실 0.90% · 전자제품 0.34% · 같은 카테고리 비율 61~76% |
| `05_cohort_and_value.sql` | 첫 구매 월 코호트, 첫 주문 금액 4분위(`NTILE`)별 재구매율 | 코호트별 추이, 금액 구간별 비교 |
| `06_purchase_intervals.sql` | `LAG`로 구매 단계별 간격 분포 | 1시간 안 재주문 비중: 첫→두 번째 28.5% → 두→세 번째 19.3% → 세→네 번째 이후 11.0% |
| `optimization/` | 같은 집계를 '조인 후 집계'와 '집계 후 조인'으로 비교 (`EXPLAIN ANALYZE`) | 결과 동일, 조인 후 행 수 1,508만 → 9.9만, 실행 시간 약 2배 단축 |

## 쿼리 최적화 예시

위치 테이블(`olist_geolocation_dataset`, 약 100만 행)은 우편번호 앞자리 하나에 위치 행이 수십 개씩 있어, 고객과 바로 조인하면 중간 결과가 1,508만 행으로 불어납니다. 우편번호별로 합계·건수를 먼저 줄인 뒤 조인하면 중간 결과가 9.9만 행이 되고, 평균을 '합계 / 건수'로 다시 계산해 결과는 정확히 같습니다.

`run_sql.py`가 두 쿼리의 결과가 같은지 확인하고, 5회 실행한 시간의 중앙값과 실행계획을 `outputs/sql/query_optimization.csv`, `explain_before.txt`, `explain_after.txt`에 저장합니다. 측정 예: 513ms → 229ms (CSV 읽기 시간 포함, PC마다 다름).

## 정의

- 고객: `customer_unique_id` / 주문: `order_status = 'delivered'`만 사용
- 관찰 마감일: 배송 완료 주문의 마지막 구매 시각
- N일 재구매: 첫 구매가 (마감일 − N일) 이전인 고객 중, 두 번째 주문이 첫 주문 후 N일 이내인 비율
- 예측 모델용 재구매: 두 번째 주문이 첫 주문 후 24시간 초과 ~ 30일 이내 (같은 날 나눠 결제한 주문 제외)
- 주문 대표 카테고리: 상품 수가 가장 많은 카테고리, 동률이면 알파벳 순
