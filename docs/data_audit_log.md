## 1. 감사 목적

본 분석에 사용되는 Olist 원본 데이터의 구조, 결측치, 중복,
식별자 및 테이블 관계를 확인하여 이후 분석에서 발생할 수 있는

## 6. 현재 확정한 분석 원칙

1. 원본 데이터는 수정하지 않는다.
2. 고객 수는 `customer_unique_id`의 고유 개수로 계산한다.
3. 주문 수는 `order_id`의 고유 개수로 계산한다.
4. 상품 행 수를 주문 횟수로 사용하지 않는다.
5. 주문 단위 데이터와 주문상품 단위 데이터를 분리한다.
6. 결측치는 확인 즉시 삭제하지 않는다.
7. 결측이 발생한 업무적 이유와 분석 영향을 먼저 검토한다.
8. 리뷰 텍스트 결측은 리뷰 점수 분석에서 삭제 사유로 사용하지 않는다.
9. 지리 데이터는 중복 구조를 정리한 후 사용한다.
10. 전체 기간 반복구매율과 30·60·90·180·365일 반복구매율을 구분한다.

### 9.3 주요 해석

#### 정상적으로 확인된 키

다음 키는 결측과 중복이 없어 각 테이블의 행을 고유하게 식별할 수 있다.

- `customers.customer_id`
- `orders.order_id`
- `products.product_id`
- `sellers.seller_id`
- `category_translation.product_category_name`
- `order_items.[order_id, order_item_id]`
- `payments.[order_id, payment_sequential]`

특히 주문상품과 결제 데이터는 단일 `order_id`가 아니라
각각의 복합키를 사용해야 행을 고유하게 식별할 수 있다.

#### 리뷰 ID 중복

리뷰 데이터는 전체 99,224행이지만
고유한 `review_id`는 98,410개다.

따라서 전체 행 수와 고유 리뷰 ID 수에는 814행의 차이가 있다.

또한 1,603행이 중복된 `review_id` 그룹에 포함되어 있으므로
`review_id`만으로 리뷰 데이터의 각 행을 고유하게 식별할 수 없다.

`duplicate_key_rows`는 단순히 추가로 발생한 중복 행 수가 아니라,
중복된 키를 가진 원본 행 전체의 수다.

예를 들어 동일한 ID가 두 행에 존재하면 두 행 모두
중복 관련 행으로 집계된다.

### 9.4 현재 처리 상태

리뷰 중복은 아직 제거하지 않는다.

다음 사항을 추가로 확인한 후 처리 기준을 결정한다.

- 동일한 `review_id`가 서로 다른 주문에 연결되는지
- 동일 주문에 여러 리뷰가 존재하는지
- `review_id + order_id` 조합이 고유한지
- 중복 리뷰의 평점과 작성 시각이 서로 다른지
- 실제 중복 데이터인지 정상적인 리뷰 수정 또는 재등록 기록인지

### 10.2 검증 결과

| 확인 항목 | 결과 |
|---|---:|
| 전체 리뷰 행 수 | 99,224 |
| 고유 review_id 수 | 98,410 |

| 여러 리뷰 행을 가진 주문 수 | 547 |

---

### 10.3 주요 해석

`review_id`는 리뷰 테이블에서 단독 고유키로 사용할 수 없다.

중복된 789개의 `review_id`는 모두 서로 다른 주문에 연결되어 있다.
따라서 반복된 `review_id` 행은 동일 주문 내 단순 중복 행으로 볼 수 없다.

`review_id + order_id` 조합에서 중복 행이 0건으로 확인되었으므로,
두 컬럼의 조합은 현재 데이터에서 각 리뷰 행을 고유하게 식별한다.

또한 547개의 주문에는 리뷰 행이 두 개 이상 존재한다.
따라서 `order_id` 역시 리뷰 테이블에서 단독 고유키가 아니다.

---

### 10.4 분석상 영향

리뷰 원본 데이터의 행 식별에는 다음 복합키를 사용한다.

- `review_id`
- `order_id`

리뷰 데이터를 주문 데이터와 직접 조인하면
여러 리뷰가 존재하는 주문이 여러 행으로 증가할 수 있다.

향후 주문 단위 분석에 리뷰 데이터를 사용할 경우에는
주문별 리뷰 집계 테이블을 먼저 생성한 후 조인해야 한다.

가능한 집계 방식은 다음과 같다.

- 주문별 평균 리뷰 점수
- 주문별 최종 리뷰 점수
- 주문별 최초 리뷰 점수
- 주문별 리뷰 개수
- 텍스트 리뷰 작성 여부

실제 집계 기준은 리뷰 분석 목적을 정한 후 결정한다.

---

### 10.5 현재 처리 상태

- 중복된 `review_id` 행을 삭제하지 않는다.
- 리뷰 원본 행의 식별키로 `review_id + order_id`를 사용한다.
- 주문별 리뷰 집계 기준은 아직 확정하지 않는다.
- 반복구매 핵심 분석에서는 리뷰 데이터를 당장 결합하지 않는다.

- 리뷰와 주문

카테고리 번역 관계에서는 카테고리가 존재하는 상품 32,341개 중
13개 상품이 영어 번역 테이블과 연결되지 않았다.

미연결 상품 13개는 2개의 서로 다른 포르투갈어 카테고리에 속한다.

이는 상품의 카테고리 값이 없는 문제가 아니라,
카테고리 번역 테이블에 해당 카테고리명이 포함되지 않은 문제다.

### 11.4 분석상 영향

영어 카테고리명을 이용한 분석에서는 해당 13개 상품의 카테고리명이
결측값으로 변환될 수 있다.

따라서 카테고리 번역 테이블과 조인할 때는 `left join`을 사용하고,
번역되지 않은 카테고리를 이유로 상품 행을 삭제하지 않는다.

번역이 없는 카테고리는 다음 중 하나의 방식으로 처리할 수 있다.

- 원본 포르투갈어 카테고리명을 그대로 사용
- 별도의 영어 번역값을 수동으로 추가
- `untranslated_category`로 분류

최종 처리 방식은 미연결된 두 카테고리명을 확인한 후 결정한다.

### 18.2 H&M 데이터

H&M 데이터는 고객별 구매 날짜, 상품, 가격 및 판매 채널 정보를 제공하며
약 2년의 거래기간을 가지고 있어 30·60·90·180·365일 분석이 가능하다.

다만 명시적인 order_id가 없고,
한 행은 주문이 아니라 구매상품 한 개를 의미한다.

따라서 H&M 분석에서는 다음 조합을 하나의 구매 기회로 잠정 정의한다.

- customer_id
- t_dat
- sales_channel_id

같은 고객이 같은 날짜와 같은 채널에서 구매한 여러 상품은
하나의 구매 기회로 집계한다.

같은 날짜와 채널에서 실제로 여러 주문이 발생한 경우에는
이를 구분할 수 없다는 한계가 있다.

또한 H&M은 단일 패션 유통기업이며 온라인·오프라인 거래가 포함되어 있어
다중 판매자 온라인 마켓플레이스인 Olist와 사업 구조가 다르다.

---

### 18.3 REES46 다중 카테고리 데이터

REES46 데이터는 온라인 다중 카테고리 쇼핑몰의
조회, 장바구니, 구매 이벤트를 포함한다.

구매 이벤트 분석에서는 다음 조합을 구매 기회로 사용할 수 있다.

- user_id
- user_session

사업 구조는 H&M보다 Olist에 가깝지만,
관찰기간이 약 7개월이므로 365일 재구매율을 계산하기 어렵다.

또한 전체 이벤트 규모가 매우 커서
구매 이벤트만 선별하는 별도의 전처리가 필요하다.

### 18.4 현재 평가

H&M은 장기간 관찰과 대규모 고객 표본 측면에서
기간별 재구매율의 주 외부 비교 데이터로 적합하다.

REES46 다중 카테고리 데이터는 온라인·다중 카테고리라는

## 23. 최종 프로젝트 방향 조정 기록

기록일: 2026-07-18

### 23.1 최종 목적

프로젝트의 최종 목적을 다음과 같이 확정한다.

> Olist의 고객 재구매율을 객관적으로 진단하고, 재구매 가능성과 관련된
> 고객 경험·상품·주문 특성을 식별하여 재구매율 개선을 위한 우선 고객군과
> 실행 전략을 제안한다.

분석기법과 머신러닝은 목적이 아니라 비즈니스 질문과 CRM 자원 배분을 지원하는 수단으로 사용한다.

### 23.2 최종 결과물의 다섯 축

1. 재구매율 진단
2. 개선 기회 탐색
3. 재구매 가능성 예측
4. 실행형 고객 세그먼트
5. CRM 전략 및 성과 측정 설계

외부 비교가 끝난 뒤에는 Olist 월별 코호트와 첫 구매 특성 마트를 시작으로
카테고리·주문가치·배송·리뷰·결제·지역 분석을 순차 수행한다.

### 23.3 해석 범위

현재 데이터는 과거 관찰 데이터이며 캠페인 실행 결과가 없다. 따라서 관찰된 연관성을
원인이나 정책 효과로 표현하지 않는다. 전략은 `검증 가설`로 제안하고 실제 증분 효과는
향후 실험군·대조군 비교로 확인하도록 설계한다.

### 23.4 개선 기회와 모델의 역할

개선 우선순위는 고객 규모, 재구매율 격차, 관찰 고객가치, 기업의 개입 가능성을 함께 평가한다.
이는 통계적 효과 추정식이 아니라 의사결정 프레임이다.

예측 모델은 고객별 재구매 가능성을 산출해 CRM 대상을 압축하는 역할만 한다.
첫 주문 직후 모델과 경험 완료 후 모델을 구분하여 예측 시점 이후 정보가 유입되는
데이터 누수를 방지한다. 최종 타깃 기간은 30·60·90일 양성 수와 안정성을 확인한 뒤 결정한다.

### 23.5 모델 검증과 실행 연결

- 시간 순서 및 고객 단위 분할을 우선한다.
- Accuracy보다 PR-AUC, Precision, Recall, F1, Calibration과 Lift@5·10·20%를 사용한다.
- Lift는 캠페인 효과가 아니라 재구매 고객 밀집도를 식별하는 능력으로 해석한다.
- 최종 세그먼트는 재구매 가능성, 관찰 고객가치, 첫 구매 경험, 개입 가능성을 결합한다.
- CRM 플레이북에는 실행 가설, 시점, 메시지·혜택, Primary KPI와 Guardrail KPI를 포함한다.
- 비용·마진 자료가 없으므로 기대효과는 실제 성과가 아닌 가정 기반 시나리오로만 제시한다.

### 23.6 현재 작업 순서에 미치는 영향

당장 다음 단계는 기존 계획대로 REES46 구매 이벤트 대체키 감사다.
이후 REES46 재구매율과 공개 산업 벤치마크를 완료하기 전에는
Olist가 시장 평균보다 낮다고 최종 결론 내리지 않는다.

외부 비교 완료 후에는 프롬프트에 확정된 25단계 순서에 따라 한 번에 한 단계씩 진행하고,
매 단계 결과 검증 후 네 개 관리 문서를 실제 작업일로 갱신한다.

### 24.1 분석 질문과 필요성

REES46의 `purchase` 1행은 상품 이벤트이며 명시적인 주문번호가 없다.

### 26.2 적용한 분석 개념과 코딩 방식

- 고객 Grain: 구매 이벤트당 1행을 고객당 1행으로 변환

- 불변조건 검증: 고객키 고유성, 구매 이벤트 합계, 구매 순서와 날짜 논리 확인

## 42. Olist CRM 실험 ITT 분석 파이프라인 사전 구현
기준일: 2026-07-24

### 42.1 목적과 분석 원칙

- 실제 캠페인 결과가 들어오기 전에 Primary KPI·Guardrail·신뢰구간 계산 코드를 고정하고 오류를 검증했다.
- 현재 실험 결과가 없으므로 무효과·상대 +30%·상대 +75%의 세 합성 시나리오를 생성했다.
- 모든 합성 행과 결과에 `synthetic_data_flag=True` 및 경고문을 기록해 실제 성과와 분리했다.
- 주 분석대상은 무작위 배정 후 30일 결과 관찰이 완료된 고객이며 발송 실패·미열람은 원래 배정군에 유지한다.
- Primary 효과는 ITT 재구매율 절대 차이와 위험비로 보고한다.

### 42.2 통계 방법

- 낮은 이항 발생률을 고려해 재구매율 차이의 95% 구간은 Newcombe-Wilson 방법을 사용했다.
- 상대 위험비는 로그 척도 95% 구간을 계산했다.
- 희소 사건의 양측 검정은 Fisher exact test를 사용했다.
- 연속형 관찰 공헌이익은 현재 평균 차이 정규근사를 구현했으며 실제 값의 비대칭성이 크면 부트스트랩 구간으로 교체하도록 분석 명세에 기록했다.
- p-value만으로 성공을 판정하지 않고 효과 크기·신뢰구간·사건 수·Guardrail·비용을 함께 보고하도록 했다.

### 42.3 합성 시나리오 검증 결과

- 무효과: 실험군 41/2,333, 대조군 41/2,334, 차이 +0.0008%p, 95% 구간 -0.7690~+0.7706%p
- 상대 +30%: 실험군 54/2,333, 대조군 41/2,334, 차이 +0.5580%p, 95% 구간 -0.2600~+1.3893%p, Fisher p=0.179743
- 상대 +75%: 실험군 72/2,333, 대조군 41/2,334, 차이 +1.3295%p, 95% 구간 +0.4485~+2.2368%p, Fisher p=0.003121
- +30% 합성 효과가 유의하지 않은 결과는 효과가 없다는 뜻이 아니라 현재 표본에서 구간이 넓다는 이전 검정력 결과를 재현한다.
- 위 수치는 전부 합성 데이터 계산 검증이며 캠페인 효과가 아니다.

### 42.4 품질 검증

- 합성 시나리오 3개 × 고객 4,667명 = 14,001행
- 각 시나리오 고객 중복 0건, 합성 표시 누락 0건
- Primary 결과 3개 모두 합성 표시 유지

- 모든 메시지를 발송 실패로 바꾼 검증에서도 ITT 분모는 4,667명 유지
- 총 12개 품질검사를 모두 통과했다.

## 51. Olist 불균형 처리·양성 오버샘플링 검증
기준일: 2026-08-03

### 51.1 실험 설계

- 시간순 학습·선택검증·보정·테스트 분할을 유지했다.
- 불균형 처리는 학습 데이터에만 적용하고 검증·보정·테스트의 원래 양성률은 변경하지 않았다.
- 기준 로지스틱과 양성 가중치 5·10·20·balanced, Random Oversampling 목표 양성률 1%·2%·5%를 비교했다.
- 검증 PR-AUC를 1차 후보 기준으로 사용하고 Lift·Recall·Calibration·FP·FN·순위 중첩을 함께 확인했다.

### 51.2 검증 결과

- 기준 검증 PR-AUC 0.007454, Lift@10% 1.817553, 포착 양성 8명
- 2% 오버샘플링 검증 PR-AUC 0.007555로 +0.000101이었지만 Lift@10%는 1.363165, 포착 양성 6명으로 악화
- 가중치 5·10·20의 검증 Lift@10%는 모두 0.908777, balanced는 1.135971
- 높은 가중치일수록 평균 예측확률이 실제율 0.507088%를 크게 초과해 Calibration이 악화

### 51.3 사후 테스트 진단

- 테스트는 프로젝트에서 이미 사용했으므로 새로운 독립 성능 근거가 아니라 사후 연구 진단이다.
- 기준 PR-AUC 0.007821, Lift@10% 1.758753, 포착 양성 19명
- 2% 오버샘플링 PR-AUC 0.007901, Lift@10% 1.851318, 포착 양성 20명
- 개선은 양성 1명과 PR-AUC +0.000080에 그쳤다.
- 상위 10% Jaccard 중첩은 0.651760이며 원시 평균확률 2.010421%는 실제율 0.622299%의 3.230634배였다.
- Platt 보정 후 Brier score는 0.006186으로 기준 원시 0.006185와 사실상 같았다.

### 51.4 결론과 산출물
