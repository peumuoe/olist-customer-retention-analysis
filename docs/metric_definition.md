# Olist 반복구매 분석 지표 정의서

## 1. 프로젝트 목적

Olist 고객의 반복구매 행동을 분석하고, 반복구매 고객이 선호하는
상품군과 재구매 시점을 파악하여 데이터 기반 CRM 전략을 설계한다.

---

## 2. 분석 단위

분석 목적에 따라 데이터 단위를 구분한다.

### 주문 단위 데이터

- 1행 = 1개의 주문
- 고객 수, 주문 수, 반복구매율, 재구매 간격, 배송기간 분석에 사용한다.

### 주문상품 단위 데이터

- 1행 = 한 주문에 포함된 상품 1개
- 상품 카테고리, 가격, 판매자, 교차구매 분석에 사용한다.

주문상품 데이터를 이용해 고객 수나 주문 수를 계산할 때는
반드시 customer_unique_id와 order_id의 중복을 제거한다.

---

## 3. 고객 식별자

고객 식별에는 customer_id가 아니라 customer_unique_id를 사용한다.

- customer_id:
  주문 단위로 부여되는 고객 ID이며 동일 고객이라도 주문마다 달라질 수 있다.

- customer_unique_id:
  여러 주문에 걸쳐 동일 고객을 식별하는 고유 ID다.

---

## 4. 유효 주문

기본 반복구매 분석에서는 다음 조건을 모두 만족하는 주문을 사용한다.

- order_status == "delivered"
- order_purchase_timestamp가 존재한다.
- customer_unique_id가 존재한다.
- order_id가 존재한다.

취소, unavailable, invoiced, processing, shipped 상태의 주문은
원본 데이터에서 삭제하지 않지만 기본 반복구매율 계산에서는 제외한다.

---

## 5. 분석 기준일

분석 기준일은 유효 주문 중 가장 늦은 order_purchase_timestamp로 정의한다.

분석 기준일은 각 고객에게 30일, 60일, 90일, 180일, 365일의
관찰 가능 기간이 확보되었는지 판단하는 데 사용한다.

---

## 6. 주문 횟수

동일한 customer_unique_id가 생성한 서로 다른 order_id 개수를
고객의 주문 횟수로 계산한다.

상품 개수 또는 order_items의 행 개수를 주문 횟수로 사용하지 않는다.

---

## 7. 전체 기간 반복구매 고객 비율

전체 데이터 기간 동안 2회 이상 유효 주문을 한 고객의 비율이다.

계산식:

2회 이상 주문 고객 수 / 1회 이상 주문한 전체 고객 수

이 지표는 고정된 관찰기간이 없으므로 30일, 60일 등의
기간 기준 반복구매율과 구분한다.

기존에 산출한 3.12%는 이 지표에 해당할 가능성이 높으며,
새로운 분석 코드로 다시 검증한다.

---

## 8. N일 반복구매율

첫 구매 후 N일 이내에 두 번째 유효 주문을 한 고객의 비율이다.

분석 기간:

- 30일
- 60일
- 90일
- 180일
- 365일

### 분모

첫 구매일로부터 분석 기준일까지 최소 N일의 관찰기간이 확보된 고객 수

### 분자

분모에 포함된 고객 중 첫 구매 후 N일 이내에
두 번째 유효 주문을 한 고객 수

### 계산식

N일 반복구매율 =
첫 구매 후 N일 이내 재구매한 고객 수
/
최소 N일의 관찰기간이 확보된 고객 수

최근에 처음 구매하여 충분한 재구매 기회가 없었던 고객은
해당 기간의 분모에서 제외한다.

---

## 9. 재구매 간격

고객의 첫 번째 유효 주문과 두 번째 유효 주문 사이의 일수다.

계산식:

second_order_timestamp - first_order_timestamp

단위:

일(day)

재구매 간격은 양수여야 하며 같은 시각 또는 음수인 값은 별도로 확인한다.

---

## 10. 고객 유형

고객별 유효 주문 횟수를 기준으로 구분한다.

- single_customer:
  유효 주문이 1회인 고객

- repeat_customer:
  유효 주문이 2회 이상인 고객

고객 유형은 전체 데이터 기간 기준으로 산출한다.

---

## 11. 카테고리 선호 지표

### 카테고리 고객 침투율

특정 고객 집단 중 해당 카테고리를 한 번 이상 구매한 고객 비율이다.

계산식:

해당 카테고리 구매 고객 수
/
해당 고객 집단의 전체 고객 수

재구매 고객과 단일 구매 고객의 카테고리 선호를 비교할 때
우선적으로 사용한다.

### 카테고리 구매 비중

해당 고객 집단의 전체 주문상품 중 특정 카테고리가 차지하는 비율이다.

계산식:

해당 카테고리 주문상품 수
/
해당 고객 집단의 전체 주문상품 수

상품을 많이 구매한 일부 고객의 영향을 받을 수 있으므로
카테고리 고객 침투율과 함께 해석한다.

---

## 12. 첫 구매 카테고리별 N일 반복구매율

첫 주문에서 특정 카테고리를 구매한 고객 중
N일 이내에 다시 구매한 고객 비율이다.

계산식:

첫 주문에서 해당 카테고리를 구매하고
N일 이내 재구매한 고객 수
/
첫 주문에서 해당 카테고리를 구매했으며
최소 N일의 관찰기간이 확보된 고객 수

한 주문에 여러 카테고리가 포함된 경우
한 고객이 여러 카테고리에 포함될 수 있다.

이 지표는 카테고리가 재구매를 유발한다고 증명하는 지표가 아니라,
재구매 가능성이 상대적으로 높은 고객군을 탐색하기 위한 지표다.

---

## 13. 결과 해석 원칙

- 비율 차이가 존재한다는 사실과 원인에 대한 결론을 구분한다.
- 관찰 데이터만으로 인과관계를 단정하지 않는다.
- 평균뿐 아니라 중앙값, 분포, 사분위수도 함께 확인한다.
- 외부 업계 평균과 비교할 때는 측정 기간과 고객 정의가 동일한지 확인한다.
- 분석 결과는 구체적인 CRM 액션과 검증 방법으로 연결한다.

## 24. 조인 시 주의사항

- customers와 orders의 조인 결과는 주문당 1행을 유지해야 한다.
- orders와 order_items를 조인하면 상품 수만큼 행이 증가한다.
- orders와 payments를 조인하면 결제수단 수만큼 행이 증가할 수 있다.
- orders와 reviews를 조인하기 전에 주문당 리뷰 수를 확인한다.
- geolocation은 우편번호별 중복 좌표를 먼저 집계한다.
- 고객 수는 customer_unique_id의 고유 개수로 계산한다.
- 주문 수는 order_id의 고유 개수로 계산한다.

## 25. REES46 구매 이벤트

지표명:

REES46 구매 이벤트

쉬운 설명:

같은 고객이 하나의 사용자 세션 안에서 기록한 하나 이상의 `purchase` 상품행을
구매 과정 1회로 집계한 값이다.

분석 목적:

상품 단위 purchase 로그를 구매 횟수로 과대 계산하지 않고 고객별 재구매 행동을 측정한다.

대체키:

`user_id + user_session`

계산식:

`event_type == "purchase"`인 행을 선별한 뒤
`user_id`, `user_session` 조합당 1개의 구매 이벤트로 집계한다.

포함 기준:

- `event_type == "purchase"`
- `user_id`가 존재한다.
- `user_session`이 존재한다.
- `event_time`이 정상 변환된다.

제외 기준:

- purchase가 아닌 view·cart 이벤트
- 고객·세션·시각을 식별할 수 없는 행

관찰 종료일:

현재 보유 파일의 최대 이벤트 시각인 `2019-11-30 23:59:59 UTC`

데이터 단위:

고객·세션별 구매 이벤트 1개 = 1행

사용 파일:

- `data/external/rees46/raw/2019-Oct.csv`
- `data/external/rees46/raw/2019-Nov.csv`
- 후속 생성 예정 구매 이벤트 마트

비교 가능성:

Olist·H&M과 기간별 재구매율의 계산 구조는 맞출 수 있지만,
REES46은 주문번호가 없는 이벤트 로그이므로 구매 이벤트가 대체키 기반이라는 차이를 명시한다.

한계:

- 세션이 실제 주문번호나 결제번호와 완전히 같다고 증명할 수 없다.
- 한 세션 안의 여러 실제 결제가 하나로 합쳐질 수 있다.
- 30분·60분 간격 분리 결과는 민감도 분석으로 함께 확인한다.
- 현재 두 달 데이터로 90일 이상 재구매율을 계산할 수 없다.

구현 파일:

`data/external/rees46/processed/rees46_purchase_events.csv`

구현 검증 결과:

- 고객·세션 구매 이벤트 1,402,758행
- 복합키 중복 0건
- 구매 고객 697,470명
- 원본 purchase 상품행 1,659,788건 보존
- 필수 식별자·시각 결측 0건

## 26. REES46 기간별 재구매율의 관찰 기준

첫 구매 정의:

고객별 구매 이벤트를 `purchase_event_start`, `purchase_event_key` 순으로 정렬했을 때
첫 번째로 관찰된 구매 이벤트다. 고객 생애 최초 구매를 의미하지 않는다.

두 번째 구매 정의:

동일한 정렬 기준에서 두 번째로 관찰된 구매 이벤트다.

관찰 종료일:

`2019-11-30 23:59:44 UTC`

N일 적격 고객 정의:

첫 관찰 구매시각부터 관찰 종료일까지 N일 이상의 시간이 존재하는 고객이다.

현재 적격 고객:

- 30일: 347,118명
- 60일: 14,064명
- 90일: 0명

해석 제한:

- 30일은 주 외부 비교 후보로 사용한다.

타기팅 규칙 평가:

```text
고객 커버리지(%)
= 규칙 선택 고객 수 / 기준점 적격 고객 수 × 100

양성 포착률(%)
= 규칙 선택 고객 중 양성 수 / 전체 적격 고객 중 양성 수 × 100

선택 고객 양성률(%)
= 규칙 선택 고객 중 양성 수 / 규칙 선택 고객 수 × 100

타기팅 리프트
```

## 40. CRM 무작위 실험 지표 정의
기준일: 2026-07-24

- **증분효과**: 실험군 결과율에서 대조군 결과율을 뺀 차이다. 모델 Lift와 구분한다.
- **무작위 배정 단위**: `customer_unique_id`다. 한 고객은 하나의 실험군에만 속한다.
- **층화 무작위화**: 가치구간·지역 버킷·점수 5분위가 비슷하게 분포하도록 층 안에서 실험군과 대조군을 배정한다.
- **ITT(Intention-to-Treat)**: 실제 메시지 도달·열람 여부와 관계없이 최초 배정군 기준으로 모든 고객을 분석한다.
- **Primary KPI**: `첫 주문 후 24시간 초과~30일 이내 후속 배송 완료 주문 고객 수 / 무작위 배정 고객 수`다.
- **절대 효과(%p)**: `실험군 재구매율 - 대조군 재구매율`이다.
- **상대 효과**: `(실험군 재구매율 / 대조군 재구매율) - 1`이다.
- **검정력**: 실제로 사전에 가정한 효과가 있을 때 통계 검정이 이를 발견할 확률이다. 계획값은 80%다.
- **MDE**: 주어진 표본수·유의수준·검정력으로 탐지할 수 있는 최소 효과다.
- **Guardrail KPI**: 수신거부율, 불만율, 연락·혜택비 차감 후 증분 공헌이익이다. 현재 Olist 데이터만으로는 계산할 수 없다.
- Secondary KPI와 하위집단 결과는 Primary KPI와 구분하며 탐색 결과로 표시한다.

- **증분 공헌이익**: `실험군과 대조군의 고객당 공헌이익 차이 - 고객당 연락비 - 고객당 혜택비`다.
- 클릭·열람은 Secondary 또는 진단 지표이며 Primary 재구매율을 대체하지 않는다.

## 42. CRM 실험 분석 지표·통계 정의
기준일: 2026-07-24

- **분석 사전등록**: 결과를 보기 전에 모집단·KPI·효과척도·신뢰구간·검정·결측·중단 규칙을 고정하는 것이다.
- **절대 위험차이**: `실험군 재구매율 - 대조군 재구매율`이며 `%p`로 보고한다.
- **위험비**: `실험군 재구매율 / 대조군 재구매율`이며 1이 두 군의 비율이 같다는 기준이다.
- **95% 신뢰구간**: 같은 설계를 반복할 때 계산된 구간의 약 95%가 참 효과를 포함하도록 구성된 절차의 결과다. 현재 구간이 참 효과를 95% 확률로 포함한다는 뜻으로 표현하지 않는다.
- **Newcombe-Wilson 구간**: 두 독립 이항비율의 Wilson 구간을 결합해 위험차이의 구간을 계산하는 방법이다.
- **Fisher exact test**: 양 군의 사건·비사건 2×2 표에서 희소 사건을 고려해 양측 p-value를 계산한다.
- **p-value**: 두 군의 참 비율이 같다는 가정 아래 현재 이상으로 극단적인 표본 결과가 나올 확률이다. 효과가 없을 확률이 아니다.
- **결과 관찰 성숙**: 배정 고객이 첫 주문 이후 30일을 완전히 관찰한 상태다. 미성숙 고객은 음성으로 처리하지 않는다.
- **합성 데이터**: 코드와 해석 규칙을 검증하기 위해 생성한 가상 사건이며 실제 성과로 사용하지 않는다.

## 45. 의사결정 지원·리스크·검증 지표 정의

- **STOP**: 효과 또는 수익성이 음수이거나 사전 위해 한계를 초과해 확대하지 않는 상태다.
- **NO DECISION**: 무작위화·대조군·결과성숙·필수 데이터가 훼손돼 실험으로 사업 판단을 할 수 없는 상태다.
- **시뮬레이션 근거**: 가정한 효과에서 표본과 의사결정 규칙이 어떻게 작동하는지 확인하는 민감도 자료이며 기대효과 예측이 아니다.

## 46. 재구매 시간 생존분석 지표 정의
기준일: 2026-07-24

- **시간 원점**: 고객별 첫 관찰 배송 완료 주문 시각이다. 고객 생애 첫 구매를 의미하지 않는다.
- **사건**: 공식 정의에서는 두 번째 배송 완료 주문, 운영 정의에서는 첫 주문으로부터 24시간을 초과한 두 번째 배송 완료 주문이다.
- **기간**: 시간 원점부터 사건 발생시각 또는 관찰 종료시각까지의 일수다.
- **우측 중도절단**: 관찰 종료 전 사건이 확인되지 않았지만 이후 사건 가능성이 남아 있는 상태다.
- **생존함수 S(t)**: t일까지 두 번째 구매가 아직 관찰되지 않을 확률이다.
- **누적 재구매 1-S(t)**: t일까지 두 번째 구매가 관찰될 누적 확률의 Kaplan–Meier 추정치다.
- **위험집단**: 각 사건 시점 직전에 아직 사건도 중도절단도 되지 않은 고객이다.
- **Kaplan–Meier 추정량**: 사건 시점별 `(위험집단-사건 수)/위험집단`을 누적 곱해 S(t)를 계산한다.
- **Greenwood 분산·log-log 구간**: Kaplan–Meier 추정치의 95% 신뢰구간 계산에 사용한다.
- **독립 중도절단 가정**: 같은 시점의 위험집단에서 중도절단 여부가 향후 사건 가능성과 무관하다는 가정이다. 본 데이터에서는 달력 코호트 변화로 제한될 수 있다.
- **고정창 KPI와의 차이**: 고정창 KPI는 전체 기간을 관찰한 고객만 분모로 쓰고 Kaplan–Meier는 미성숙 고객의 관찰된 기간도 부분 활용한다.

## 47. 멀티호라이즌 평가 지표 정의
기준일: 2026-07-24

- **Horizon**: 예측시점 이후 결과를 관찰하는 미래 시간창이다. 그래프의 수평선을 뜻하지 않는다.
- **멀티호라이즌 분석**: 같은 예측시점에서 30·60·90일처럼 여러 결과창을 병렬 비교하는 분석이다.
- **기간별 적격 고객**: 첫 관찰 구매부터 데이터 종료까지 해당 Horizon 전체를 관찰할 수 있는 고객이다.
- **공통 90일 코호트**: 90일까지 완전히 관찰 가능한 동일 고객 집합으로, 고객 구성을 고정한 채 결과창 연장만 비교한다.
- **Q1_low·Q2·Q3·Q4_high**: 첫 주문 결제금액을 전체 고객 분포의 사분위수로 나눈 네 구간이다.
- **Quartile**: 정렬된 값을 각각 약 25%씩 포함하도록 나눈 구간이며 Q3·Q4는 관찰 주문가치 상위 절반이다.
- **기간별 Lift@10%**: 각 기간 적격 고객에서 동결 30일 점수 상위 10%의 실제율을 그 기간 전체 실제율로 나눈 값이다.
- **기간별 Recall@10%**: 각 기간 양성 중 동결 점수 상위 10%가 포착한 비율이다.
- **시간창 불일치**: 30일 확률점수를 60·90일 결과와 비교하는 상태다. 평균점수와 장기 실제율 차이는 정식 Calibration 오류가 아니다.
- **Primary Horizon**: 실험의 성공·실패를 판정하는 사전 지정 핵심 결과창이다.
- **Secondary Horizon**: 효과 지속이나 지연 결과를 보조적으로 확인하지만 Primary 판정을 대체하지 않는 결과창이다.

## 48. 모델 오류·수용량·비용 민감도 지표 정의
기준일: 2026-08-03

- **True Positive(TP)**: 상위 대상에 선택됐고 관찰기간 안에 재구매한 고객이다.
- **False Positive(FP)**: 선택됐지만 관찰기간 안에 재구매하지 않은 고객이다. CRM에 반응하지 않을 고객과 같은 뜻은 아니다.
- **False Negative(FN)**: 선택되지 않았지만 관찰기간 안에 재구매한 고객이다.
- **True Negative(TN)**: 선택되지 않았고 관찰기간 안에 재구매하지 않은 고객이다.
- **Precision**: `TP/(TP+FP)`이며 선택 고객 중 관찰 재구매자의 비율이다.
- **Recall**: `TP/(TP+FN)`이며 전체 관찰 재구매자 중 선택 고객이 포착한 비율이다.
- **False Discovery Rate**: `FP/(TP+FP)`이며 희소 사건에서는 Lift가 1보다 높아도 매우 높을 수 있다.
- **Capacity frontier**: 선택 비율별 접촉 수·Precision·Recall·Lift·한계 포착률을 연결한 표다.
- **한계 구간 관찰률**: 이전 선택 비율에서 현재 비율로 추가된 고객만의 과거 재구매율이다.
- **관찰 재구매자 1명당 접촉**: `선택 고객/선택 고객 중 관찰 재구매자`다. 증분구매 1건당 발송 수가 아니다.
- **손익분기 증분전환율**: `고객당 접촉비/증분구매 1건당 공헌이익`이다.
- **비용 민감도**: 실제 비용값이 없을 때 여러 가정에서 손익분기 조건이 어떻게 달라지는지 보여주며 기대수익을 예측하지 않는다.

## 49. 최종 실행형 CRM 플레이북 정의
기준일: 2026-08-03

- **실행형 세그먼트**: 고객을 설명하는 데서 끝나지 않고 서로 다른 대상·처치·시점·제외·측정 규칙에 연결된 집단이다.
- **Treatment**: 무작위 실험의 실험군에만 제공하는 추가 메시지·혜택·노출이다.
- **Control**: 실험성 추가 처치 없이 정상 거래성 커뮤니케이션을 유지하는 비교집단이다.
- **콘텐츠 모듈**: 같은 처치 목적 안에서 첫 주문 카테고리에 맞춰 관련성을 조정한 메시지 내용이다. 별도 인과효과를 의미하지 않는다.
- **Eligibility**: 가치구간·모델순위·첫 주문 확인·동의·연락 가능성 등 발송 전 충족해야 하는 조건이다.
- **Suppression**: 수신거부·동의 무효·연락불가·취소·부정계정·중복실험·빈도초과로 발송하지 않는 규칙이다.
- **DO_NOT_LAUNCH**: 현재 데이터와 운영 상태에서 안전하고 측정 가능한 실험 실행조건이 충족되지 않은 결정이다.
- **CONDITIONAL_RANDOMIZED_PILOT**: 조직이 모든 차단·보류 조건을 해소한 경우에만 무작위 파일럿으로 전환할 수 있다는 제안이다.
- **역사적 후보**: 과거 Olist 데이터로 정책을 재현한 고객이며 현재 접촉 가능 고객 목록이 아니다.

## 50. 최종 일관성 감사·분석 종료 정의
기준일: 2026-08-03

- **Consistency audit**: 보고서의 지표·숫자·주장·권고가 서로 충돌하지 않는지 확인하는 검사다.
- **Claim–evidence mapping**: 각 주장을 근거 수준·원천 산출물·허용 표현·금지 해석에 연결하는 방식이다.
- **Decision boundary**: 현재 근거로 허용되는 의사결정과 그 이상이 추측이 되는 경계다.
- **Exit criteria**: 분석을 종료하기 전에 필수 작업의 완료·검증불가 종료·산출물 존재를 확인하는 조건이다.
- **closed_unverifiable_with_current_data**: 필요한 결과가 없지만 프로젝트 제약상 생성할 수 없어 한계로 명시하고 닫은 상태다.
- **ANALYSIS_COMPLETE_PORTFOLIO_READY**: 현재 데이터로 가능한 분석·검증·의사결정 설계가 완료되고 최종 일관성 감사까지 통과한 상태다.

## 51. 불균형 처리·오버샘플링 검증 정의
기준일: 2026-08-03

- **Class Weight**: 양성 오분류의 학습 손실을 음성보다 크게 부여하는 방식이다.
- **Random Oversampling**: 학습 데이터의 기존 양성 행을 복원추출로 반복해 목표 양성 비율을 만드는 방식이다.
- **SMOTENC**: 연속형과 범주형 변수를 고려해 합성 소수 클래스를 만드는 방법이다. 본 분석에서는 선행 실험 결과와 과적합 위험 때문에 실행하지 않았다.
- **학습 전용 처리**: 오버샘플링과 가중치는 시간순 분할 이후 학습 데이터에만 적용하며 평가 데이터는 원래 분포를 유지한다.
- **순위 개선**: PR-AUC·Lift·Recall이 원본 검증 데이터에서 재현되는 변화다. 평균 확률 상승만으로 인정하지 않는다.
- **확률 왜곡**: 예측 평균이 실제 양성률에서 크게 벗어나 개인별 확률 해석이 부정확해지는 상태다.
- **사후 테스트 진단**: 이미 확인한 테스트에서 추가 모델을 비교하는 연구 결과이며 새 최종 모델 선택 근거가 아니다.

## 52. Portfolio BI 데이터 마트 정의
기준일: 2026-08-07

- **BI 데이터 마트**: 대시보드의 특정 의사결정 질문에 필요한 검증된 집계 데이터 묶음이다.
- **Fact Grain**: 테이블 한 행이 의미하는 최소 분석단위다. 예: 플랫폼×관찰기간, 모델×선택비율.
- **데이터 사전**: 데이터셋·컬럼의 Grain·자료형·결측·정의·원천·공개등급을 설명하는 메타데이터다.
- **Manifest**: 파일별 행·열·크기·해시·원천·기준일을 기록해 공개 패키지의 무결성을 확인하는 표다.
- **aggregate_public_portfolio**: 고객·주문 식별자 없이 공개 포트폴리오 시각화에 사용할 수 있는 집계등급이다.
- **source lineage**: 공개 Fact가 어떤 검증 산출물에서 생성됐는지 추적하는 연결정보다.
- **해석 제한 필드**: 외부 비교의 인과 제한이나 CRM 관찰값의 비증분 성격을 데이터 행에 직접 기록한 컬럼이다.
